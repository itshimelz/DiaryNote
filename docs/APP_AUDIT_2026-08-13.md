# DiaryNote application audit

**Date:** 2026-08-13  
**Method:** Static source review plus `npm run lint`, `npm run build`, and `cargo check --manifest-path src-tauri/Cargo.toml`. All three checks pass. This is not a penetration test and does not substitute for manual testing on each target OS.

## Executive summary

DiaryNote has a pleasant feature set and a clean TypeScript/Rust build, but it is not ready to describe as a secure, privacy-focused local-first app. The most serious problems are data persistence gaps for newly created notes and a lock feature that can be bypassed through normal export/AI actions and by reading the local database. The desktop save command also accepts traversal paths, making arbitrary file overwrite possible if its webview is compromised.

## Confirmed findings

### P0 — New and pasted notes may disappear after restart

**Locations:** `src/hooks/useNotesManager.ts:57-105`, `src/hooks/useNotesManager.ts:35-48`, `src/components/Modals/AppModals.tsx:314-320`.

**Reason:** `handleAddNote` adds a note to React state but never adds its ID to `dirtyNoteIdsRef`. The autosave effect therefore sees no dirty notes and writes nothing. The paste confirmation path first calls `handleAddNote`, then modifies state directly with `setNotes`; it also never marks the note dirty.

**Effect:** A user can create a note, paste text into it, see the application continue normally, close the app, and lose the note entirely. `lastSavedAt` is still updated, which makes the loss especially misleading.

**Recommendation:** Treat every add and direct state replacement as a persistence mutation. Mark the new ID dirty (or persist it immediately), route paste changes through `handleUpdateNote`, await save completion before updating saved status, and add restart-persistence tests for add, paste, undo, import, and deletion.

### P0 — Locked notes can be exported or sent to AI without unlocking

**Locations:** `src/components/CanvasControls.tsx:722-732`, `src/components/BatchActionBar.tsx:566-580`, `src/components/Modals/AppModals.tsx:285-292`, `src/App.tsx:260-323`.

**Reason:** The lock is checked for a single-note export, but the full backup, selected-note backup, multi-note context-menu export, and AI merge paths pass the original `Note` objects—including `content`—without checking `isLocked` or requiring a successful unlock. The AI merge then creates a new, unlocked note containing the synthesized protected content.

**Effect:** Anyone with an already-open app session can exfiltrate protected notes through a backup file or an external AI provider. This invalidates the expectation created by “passcode protection.”

**Recommendation:** Centralize authorization for every read/export/AI operation. Either exclude locked notes with clear feedback or require recent unlock verification for each protected note; never produce an unlocked derivative from protected material by default. Add tests for full backup, batch backup, context-menu export, and AI merge.

### P0 — Native export command permits path traversal and arbitrary overwrite

**Locations:** `src-tauri/src/lib.rs:1-19`; related webview policy: `src-tauri/tauri.conf.json:24-26`.

**Reason:** `filename` and `subfolder` are directly appended using `Path::join` with no validation, canonicalization, allowlist, overwrite protection, or save dialog. Values such as `../../.config/target` can escape `~/DiaryNote`. The content security policy is explicitly disabled (`"csp": null`), increasing the impact of any webview injection flaw.

**Effect:** Code that can invoke the Tauri command can write or overwrite files accessible to the current user, outside the intended export directory.

**Recommendation:** Do not accept paths from the webview. Use the Tauri dialog/fs APIs with an explicit user-chosen destination, or strictly allowlist bare filenames and a small fixed set of subfolders, reject separators/`..`/absolute paths, canonicalize before writing, and fail if the resolved path is outside the export root. Set a restrictive CSP.

### P1 — “Locked” content is stored and protected with weak, unsalted client-side controls

**Locations:** `src/components/NoteCard/index.tsx:491-517`, `src/lib/sqliteStorage.ts:5-20`, `src/utils/security.ts:1-15`, `src/components/Modals/SecurityModal.tsx:51-104`.

**Reason:** A lock only changes UI rendering; note bodies remain plaintext in IndexedDB. The master passcode and recovery answer use unsalted, fast SHA-256 hashes, passwords can be only four characters, and there is no retry throttling. The recovery questions are often guessable personal information.

**Effect:** Local users, malware, browser-devtools access, or a copied application profile can read protected notes directly; offline guessing is cheap. The feature is obscurity, not secure storage.

**Recommendation:** Reframe the current feature as a UI privacy screen until it is redesigned. For real protection, encrypt note content at rest with a per-user key derived by a memory-hard KDF (e.g., Argon2id), use authenticated encryption, keep salts and versioned metadata, and use OS keychain support where appropriate. Add throttling and avoid knowledge-based recovery unless its limitations are explicit.

### P1 — Storage errors are swallowed while the UI claims success

**Locations:** `src/hooks/useNotesManager.ts:35-48`, `src/lib/sqliteStorage.ts:139-215`, `src/hooks/useCanvasTransform.ts:46-63`.

**Reason:** Database save functions catch and only log errors, return `void`, and callers neither await nor observe failures. The note manager sets `lastSavedAt` after firing a save regardless of the result. Transform and settings use the same pattern.

**Effect:** Quota failures, IndexedDB errors, or storage corruption are invisible to users; they may close the app believing data is safe.

**Recommendation:** Return typed success/failure results, await persistence in the save coordinator, show a persistent unsaved/error state, retry safe transient failures, and offer export/recovery when storage fails. Ensure teardown flushes outstanding dirty writes.

### P1 — First-run migration can permanently remove the only recoverable source

**Locations:** `src/lib/sqliteStorage.ts:31-52`, `src/lib/sqliteStorage.ts:85-91`, `src/lib/sqliteStorage.ts:248-256`.

**Reason:** Initialization marks migration complete immediately after `bulkPut`, then calls `compactDatabase`, which deletes all legacy localStorage keys. If data was malformed, only partially migrated, later inaccessible, or the database is cleared after the marker remains, the fallback is sample notes—not the prior user data.

**Effect:** A migration/storage failure can turn real notes into demo content with no automatic recovery route.

**Recommendation:** Validate migrated records and counts in a transaction, retain a versioned legacy backup until a successful subsequent launch, never replace a non-empty user dataset with samples silently, and provide an explicit recovery/import prompt when the initialized database is empty.

### P1 — Import accepts unbounded, unvalidated records and settings

**Locations:** `src/lib/storage.ts:325-349`, `src/App.tsx:395-450`.

**Reason:** Import checks only that `parsed.notes` is an array. It does not impose a file-size limit, validate note field types/ranges/IDs, validate settings, reject duplicate IDs, or sanitize unusable date values.

**Effect:** A malformed or oversized file can freeze the app, poison layout values, overwrite settings such as AI endpoints, or create records that fail later features. Invalid timestamps also make merge behavior unpredictable.

**Recommendation:** Define a versioned backup schema, validate and normalize every field before merge, set a conservative file-size limit, display a dry-run count/errors preview, and only commit a validated import atomically.

### P1 — Modals and the notes drawer do not meet keyboard/screen-reader expectations

**Locations:** `src/components/Modals/SearchModal.tsx:184-198`, `src/components/Modals/SecurityModal.tsx:106-137`, `src/components/NotesSidebar.tsx:79-108,197-207`, plus other modal components with the same overlay pattern.

**Reason:** Overlays are plain `div`s with no `role="dialog"`, `aria-modal`, labelled title, focus trap, focus restoration, or background inertness. Note rows in the sidebar are clickable `div`s, so keyboard users cannot activate them. Numerous icon-only controls rely on `title` or have no accessible name.

**Effect:** Keyboard and screen-reader users can lose their position, tab into controls behind dialogs, miss control purpose, or be unable to select notes from the drawer.

**Recommendation:** Introduce one tested dialog/drawer primitive with semantic roles, focus trapping/restoration, Escape behavior, and inert background. Make note rows buttons or give them keyboard semantics. Audit icon buttons for visible labels or `aria-label`s and verify at 200% zoom.

### P2 — Undo/redo and some direct state changes are not persisted

**Locations:** `src/hooks/useHistoryState.ts:25-40`, `src/App.tsx:129-130`, `src/hooks/useNotesManager.ts:35-48`.

**Reason:** Undo/redo call `setNotes` directly; they do not mark changed/deleted records dirty nor perform a full synchronization. The autosave coordinator only writes IDs explicitly placed in `dirtyNoteIdsRef`.

**Effect:** The canvas can show an undo/redo result that disappears after restart, especially for restored/deleted content.

**Recommendation:** Make history replay go through a transaction-aware persistence action, including deletion reconciliation, and cover it with restart tests.

### P2 — The application does not scale to a large notebook despite canvas culling

**Locations:** `src/lib/sqliteStorage.ts:54,123-133`, `src/components/InfiniteCanvas.tsx:402-414`, `src/components/NotesSidebar.tsx:57-73`, `src/components/Modals/SearchModal.tsx:52-149`.

**Reason:** Initialization loads every full note via `db.notes.toArray()`. The canvas avoids rendering off-screen cards, but it still receives every note; sidebar/search/tag processing repeatedly scans complete note content. The advertised spatial query exists but is not used by the app, and `getNotesMetadata` reads every body before blanking it.

**Effect:** Startup RAM, filtering, tag extraction, minimap calculation, and interaction latency grow with the entire notebook. Large journals will become slow before rendering culling helps.

**Recommendation:** Keep a metadata index in memory, query/load bodies by viewport or on demand, use indexed search or a worker, virtualize list results, and benchmark 1k/10k notes with realistic long content.

### P2 — AI and update requests lack timeouts, cancellation, and robust privacy boundaries

**Locations:** `src/services/ai/aiMergeService.ts:71-314`, `src/utils/updateChecker.ts:42-117`, `src/App.tsx:281-343`.

**Reason:** `fetch` calls use no `AbortController`/timeout. A stalled provider leaves merge UI busy indefinitely. Gemini API keys are placed in a query string, which can be captured in URL logs. Custom AI base URLs are user-controlled without a clear warning about sending both notes and credentials to that host.

**Effect:** The app can appear stuck, users cannot cancel a costly request, and sensitive data/API credentials can be sent or logged more broadly than expected.

**Recommendation:** Add per-request timeout and cancellation, make busy state request-specific, use provider-supported header authentication where available, and show a clear data-destination warning before using custom endpoints or AI features.

### P2 — Desktop/mobile adaptivity is incomplete

**Locations:** `src-tauri/tauri.conf.json:13-22`, `src/components/InfiniteCanvas.tsx:88-108,321-369`, `src/components/NotesSidebar.tsx:80-85`.

**Reason:** The desktop window cannot go below 800×600 and interaction paths are mouse-event based rather than pointer/touch-event based. The fixed-width drawer has no compact-state alternative; the project includes Android icons but no mobile-specific input or layout handling.

**Effect:** Small windows, touch laptops, tablets, and future mobile builds will have cramped or non-native interaction; drag/pan/selection may not work with touch.

**Recommendation:** Establish supported platforms explicitly, test narrow desktop windows, migrate gesture code to Pointer Events, add touch target sizing, and design responsive drawer/control states before claiming mobile support.

### P2 — Note and generated ID collisions are possible

**Locations:** `src/App.tsx:304-305`, `src/components/NoteCard/index.tsx:811-820`, `src/components/Modals/AppModals.tsx:266-281`.

**Reason:** Several creation paths use `Date.now()` alone or a short `Math.random()` suffix. Two operations within one millisecond can generate the same ID; import does not detect duplicate IDs either.

**Effect:** A collision can replace a record in IndexedDB, corrupt links, or produce confusing selection/history behavior.

**Recommendation:** Use `crypto.randomUUID()` for all client-generated IDs and validate uniqueness during import.

### P3 — Documentation inaccurately calls Dexie “SQLite”

**Locations:** `README.md:7,13`, `src/lib/sqliteStorage.ts:1-20`.

**Reason:** Dexie is an IndexedDB wrapper; the Rust application has no SQLite plugin/database integration.

**Effect:** Contributors and users may make incorrect assumptions about storage location, backup, querying, portability, and security.

**Recommendation:** Rename the module/documentation to IndexedDB/Dexie unless SQLite is actually introduced.

## Systemic patterns

- **UI state and persistent state are not one transaction.** Add, paste, undo/redo, and save status each use different pathways, creating silent divergence.
- **Security is enforced at individual UI entry points.** The missing checks in batch export and AI merge show that protection must live in a centralized data-access policy.
- **The app is optimized for a few notes.** Full dataset loading and repeated content scans conflict with the “infinite” canvas goal.
- **Desktop WebView trust is too broad.** Disabled CSP plus a powerful filesystem command greatly amplifies any future frontend injection bug.

## Positive findings to retain

- TypeScript type checking, production web build, and Rust compilation all succeed.
- The code splits large UI areas into hooks/components and lazy-loads modals.
- Canvas render culling, debounced transforms, and animation-frame batching show good awareness of interaction performance.
- Markdown links use `noopener noreferrer`, reducing reverse-tabnabbing risk.
- The sidebar and search avoid showing locked-note titles/content in their normal display paths.

## Recommended remediation order

1. **P0:** Repair all persistence mutations and add automated restart tests for create/paste/undo/delete.
2. **P0:** Block export and AI access to locked notes until an explicit authorization model is implemented.
3. **P0:** Constrain or replace the native file-writing command; set a restrictive CSP.
4. **P1:** Redesign note protection as real encryption at rest, or change the product copy to describe it accurately.
5. **P1:** Make storage failures visible and make initialization/migration recoverable.
6. **P1:** Add backup-schema validation and import preview/limits.
7. **P1:** Implement one accessible dialog/drawer primitive, then migrate every overlay and interactive list row.
8. **P2:** Refactor loading/search around metadata and indexed/on-demand content; benchmark large datasets.
9. **P2:** Add request cancellation/timeouts and clear AI data-sharing disclosures.
10. **P2/P3:** Define supported form factors, use pointer input, use UUIDs, and correct storage documentation.
